## What it does

fzf selects from text streams and supports preview, event bindings, shell/editor integrations, and custom interactive workflows. Its README explicitly positions it as both a fuzzy finder and a terminal toolkit. [Upstream README](https://github.com/junegunn/fzf/blob/b1be3a8be1b833ce5b92fbbac11637643d60a046/README.md).

## Why it fits this list

It supplies the filter/select/preview/action building block from which small “lazy” workflows can be composed. It is adjacent infrastructure rather than a prebuilt domain dashboard.

**UX tradeoff:** A domain-specific experience depends on the source command, preview command, and bindings supplied by an integration. That flexibility shifts workflow design into shell glue or configuration. The README marks the custom completion API as experimental, not the whole project. [Usage and completion](https://github.com/junegunn/fzf/blob/b1be3a8be1b833ce5b92fbbac11637643d60a046/README.md).

These are source-backed design observations, not claims of hands-on testing.
